给自己的核心提醒

我究竟提出了什么？它与已有工作有什么不同？这种不同带来了什么价值？如果现在要写成论文，我会怎样把它说清楚？

01 / START WITH THE QUESTION

研究的三个支点：新意、价值、结构

对我而言，研究最需要持续检查的，是新颖性、有用性，以及能否把二者组织成清楚的论证。一个想法再有趣，也要放回已有工作的背景里，解释它究竟推进了哪一步。

新颖性：哪里不一样？

新系统、新交互、新算法、新架构，或者原型与实验中出现的新发现，都可能成为贡献。关键是能简洁地说出“我提出什么”，并指出与最接近的已有方案的差异。

有用性：为什么值得做？

差异需要对应到价值：功能、效率、体验、计算复杂度、理论保证、功耗或面积等。比较时要说明，在什么问题和条件下，带来了怎样的改善。

价值既可以来自解决眼前的问题，也可以来自扫清未来系统实现时会遇到的障碍。工程研究往往关心具体问题能否解决、方案是否更合适；偏基础的研究则可能通过足够一般的知识，为未来的问题提供理解与方法。

“以前没有”还需要再往前走一步。一种新界面可能在实际操作上更麻烦；一种新架构也可能在性能、功耗和面积上都没有优势。出现直觉上的好点子后，我会先快速确认新颖性，再更谨慎地检查它的价值。

“好研究”也有不同的目标层次：完成学位要求、形成扎实的研究报告，或争取能影响领域发展的成果。先理解研究与表达的基本方法，再结合自己的目标、时间与资源，确定这一阶段要做到什么程度。论文与发表是研究被理解和评价的重要载体，因此表达能力应当从一开始就纳入研究过程。

02 / THINK AND WRITE TOGETHER

让研究与写作同步推进

我希望在每个阶段都留下可以进入论文的内容。这样，写作会帮助我提早发现问题，而最后成稿主要是把已经形成的论证补充完整。

  1. 从兴趣中筛选题目

    选择自己愿意长期投入、又可能具有新意和价值的问题。经验和时间有限时，可以从成熟方向或已有备选题目入手；随着研究训练加深，再逐步独立提出问题。

    此时留下：问题描述、研究动机、初步贡献设想。

  2. 用文献检验题目

    查清别人已经做到了什么。若新意或价值不足，就回到选题；若方向成立，就进一步收紧问题范围，同时搭出引言和相关工作的骨架。

    此时留下：已有工作的分类、最接近的方案、尚未解决的缺口。

  3. 明确提案与验证计划

    说明方法的核心机制，规划实现与实验如何检验贡献。如果方案调整已经改变了研究问题，就重新检查相关工作，确认比较对象仍然合适。

    此时留下：方法章节草稿、系统框架、实现与实验计划。

  4. 通过实现和实验修正方案

    实施计划，观察结果与预期是否一致。遇到问题时，回到方案或实验设计重新判断；结果逐渐稳定后，再补全实现过程与实验章节。

    此时留下：实验条件、结果图表、异常记录、初步解释。

  5. 把已有结构写完整并准备发表

    详细展开各章，检查论点与证据是否对应，再整理成论文与发表材料。前面的阶段若一直在组织结构，最后就能减少大范围返工。

    此时留下：完整论文、发表材料、可能被追问的问题。

我的做法：定期用几句话重写“问题、差异、价值、证据”。如果其中一句越来越难写，就回头检查对应的研究环节。

03 / BUILD A MAP BEFORE A PILE

文献调研：先画地图，再深入阅读

文献调研首先要建立领域的结构。熟悉的方向，可以从导师或前辈推荐的代表工作进入；陌生的方向，可以先寻找综述，了解问题有哪些类别、方法有哪些路线。

  1. 找入口。用领域关键词加上 survey 等词检索，先查看较新、影响较大的综述和代表论文。
  2. 沿引用关系扩展。从入口论文的参考文献和后续引用中，先读约 5～10 篇摘要，形成初步轮廓，再决定哪些需要通读。
  3. 按类别补齐。把工作按问题、技术路线或系统类型分类，在每一类中找较新且有代表性的成果，避免只看某一条熟悉的路线。
  4. 回到自己的题目。确认最接近的工作是谁、尚存什么限制，以及自己的方案应该与谁比较。

初筛时可以借助发表时间、引用情况以及 ACM、IEEE 等学术数据库定位论文，但这些只是找到入口的线索。是否真正相关、比较是否公平，仍需要读到具体的问题设定、方法和评价条件。

AI 可以帮助归类和整理。对我来说，仍要保留“代表工作 → 分类地图 → 逐类比较 → 研究缺口”的路线，并核对支撑关键判断的原文。

04 / MAKE THE ARGUMENT VISIBLE

论文：把研究写成一条论证线

论文最重要的文体特征是结构清晰。读者应当先知道文章要回答什么，再逐层看到问题背景、已有工作的边界、方法如何运作，以及证据能支持什么结论。

部分要回答的问题
标题用尽量少的词，概括研究对象与核心贡献。
摘要研究什么问题，提出什么方法，得到了什么主要结果？
引言问题为什么重要，现状哪里不足，本文贡献是什么？
相关工作已有方法如何分类，本文处在什么位置，差异在哪里？
提出的方法方案由什么组成，为什么这样设计，关键机制是什么？
实现与实验如何实现和验证，条件与比较对象是什么，结果如何？
讨论结果意味着什么，哪些解释成立，又有哪些限制？
结论最终回答了什么问题，读者应该带走什么认识？

这种结构会在多个层次重复出现：标题概括全文，摘要概括主体，章节标题概括章节，段落首句概括段落。先概括，再展开，让读者在接触细节之前先获得位置感。

具体顺序和篇幅可以根据学位论文、会议论文以及不同领域的惯例调整。实际写作前，挑几篇同类型的优秀论文，或前辈的相近成果，观察它们如何分配内容。结构提供起点，最终仍要以自己的论证需要为准。

05 / ONE PARAGRAPH, ONE TOPIC

段落：先给判断，再给解释

每一段集中处理一个主题。段落开头用主题句说清本段的核心判断，后面的句子再用细节、理由和证据支撑它。主题句可以理解为“讨论对象 + 对这个对象作出的限定或判断”。

一个写作练习

主题句：模块化设计能够降低系统维护时的替换成本。

展开方向：先说明模块如何划分，再解释局部替换为何减少对其他部分的影响，最后用相应的实现记录或实验结果支撑这一判断。

支撑句要贴着主题句展开，并尽量具体。常用的展开顺序包括：从整体到部分、从概要到细节、从已知到未知、从一般到特殊；也可以先讲最重要或读者最想知道的信息，涉及操作时则沿实际步骤展开。

这些顺序也适用于段落之间的衔接、章节安排，甚至标题中词语的先后。段末是否再重申一句，可以根据阅读效果决定；整篇论文则应有明确的结论部分。

一个简单的检查方法：只读标题、摘要、各节标题和每段第一句，看看能否看懂文章主线；再检查每段余下的句子是否都在支撑开头的判断。

06 / HELP THE AUDIENCE FOLLOW

学术发表：让听众跟得上论证

学术发表可以沿用论文的基本逻辑：先给全貌，再进入细节。问题、相关工作、方法、验证和结论之间的关系，要让听众在有限时间里把握住。

问题与价值→方案与差异→实验与证据→结论与边界

演讲的感染力还可能来自话题兴趣、沟通方式和讲者的个人风格，很难完全归纳成一套规则。对大多数研究发表，我会先把结构扎实的材料做好，再通过练习把它讲清楚。

准备过程也包括排练和问答预演：能否按时讲完？哪些地方需要背景解释？听众会如何追问新颖性、比较对象、实验条件和结果限制？遇到提问时，应能回到对应的证据和页面。

07 / EVERY SLIDE HAS A JOB

幻灯片：一页只承担一个主要信息

每页先确定一个想让听众记住的信息，再围绕它安排少量有结构的文字和有意义的图表。文字与图表互相配合，听众才容易同时理解“在说什么”和“凭什么这么说”。

  • 内容做减法。压缩长段落，保持表述简洁正式；能用直观解释说明时，减少不必要的公式。公式确实承载核心方法时，再围绕关键部分解释。
  • 语言保持一致。同一个概念使用同一个词；并列的两种方案尽量采用相同句式，让比较关系一眼可见。换行也应顺着意思的边界。
  • 让文字和线条看得清。字号尽量大，字重不要过细，图中边框和连线也应有足够厚度，并与文字风格协调。
  • 把视觉注意力留给内容。选择清晰、中性的字体，使用简单背景。觉得页面空时，优先补上能解释内容的图表，而不是无意义的装饰。
  • 谨慎使用动画。动画增加理解负担，也会让先前的状态难以同时参照。交互系统的完整演示视频可能很有帮助，其他说明尽量使用可停留、可比较的画面。
  • 帮助定位。保留页码，方便问答时指向具体页面。较长的发表可以在开头给概要，并在章节切换时用目录提示进度。

我会优先参考同领域、同类型的优秀发表材料，观察它们的信息密度、图文关系和叙事节奏，再根据实际内容调整。

08 / CHOOSE TOOLS THAT SERVE THE WORK

海报、图表与制作工具

海报同样需要清楚的主线：先让人看到研究主题和贡献，再找到方法与证据。掌握论文和幻灯片的结构后，可以把同一套论证压缩到海报中，再按阅读距离与交流场景调整。

制作工具可以从自己熟悉、协作方便的选择入手。论文写作可考虑 Overleaf；幻灯片与海报使用 PowerPoint 比较直接，习惯排版语言时也可以选择 Typst。优先参考同类型成果的成熟模板，把时间留给内容和证据。

公式、伪代码、表格、曲线、示意图和视频各自还有更细的制作规范。我会在真正需要这些材料时，寻找同类成果中的优秀实例，结合具体载体继续学习。当前先牢牢记住：每一项材料都应服务于研究的解释。
